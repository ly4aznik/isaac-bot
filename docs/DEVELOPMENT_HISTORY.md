# История развития Isaac Bot

Этот документ фиксирует фактически завершённые улучшения. План будущих работ
находится в `ROADMAP.md`. Этап попадает сюда только после реализации и проверки.

## Сводка

| Этап | Статус | Главный результат |
|---|---|---|
| 0. Управление игрой | Завершён | Python запускает ран и управляет Isaac через Lua |
| 1. Среда и запись | Завершён | Версионированный протокол и запись эпизодов |
| 2. Навигация | Завершён | A*, движение к точке и проход через двери |
| Визуализация | Завершена базовая версия | Live world model и Studio для записи |
| 3. Стрельба | Завершён функционально | Выбор цели, упреждение и очистка боевой комнаты |
| 4. Уклонение | Завершён функционально | Прогноз снарядов и выбор безопасного движения во время стрельбы |
| 5–6. Комнаты и этаж | Завершён функциональный прототип | Граф комнат, frontier, ресурсы и подготовка перехода этажей |
| Автономный цикл комнат | Экспериментальная версия | Зачистка → дверь → следующая комната без ручного запуска |

## Этап 0 — управление игрой

### Цель

Запускать стандартный ран без ручной помощи и программно управлять персонажем.

### Реализовано

- запуск `isaac-ng.exe` из Python;
- прохождение меню до стандартного рана;
- автоматические повторные попытки, пока Lua не подтвердит начало игры;
- Win32-ввод для управления меню;
- Lua callback `MC_INPUT_ACTION` для игровых действий;
- локальный UDP-мост Python → Lua → игра;
- watchdog, возвращающий ручное управление при остановке Python.

### Проверка

- Python изменил позицию персонажа через Lua;
- координата `x` изменилась с `320` до `570`;
- после действия игра вернула обновлённую позицию Python-контроллеру.

### Возможности после этапа

Бот умеет запустить ран и передавать движение, стрельбу и кнопочные действия.
Интеллектуального выбора действий ещё нет.

---

## Этап 1 — надёжная среда и запись эпизодов

### Цель

Получить воспроизводимый игровой цикл для разработки, тестирования и обучения.

### Реализовано

- протокол Isaac Bot v1;
- сообщения `HELLO`, `ACTION`, `COMMAND`, `OBSERVE`;
- sequence и action acknowledgement;
- frame, run ID и room visit ID;
- heartbeat и статистика пропущенных кадров;
- безопасный перезапуск Python-сессии;
- наблюдение за игроком, комнатой, дверями, врагами, снарядами и pickups;
- события начала рана, комнаты и этажа, урона, смерти врага и конца игры;
- автоматический рестарт;
- JSONL-запись metadata, actions, observations, events и summary;
- команды `probe`, `play`, `record`, `benchmark`.

### Проверка

- короткий transport benchmark: 301 пакет;
- повреждённых сообщений: 0;
- пропущенных наблюдений: 0;
- тестовая запись: 305 валидных JSONL-строк;
- ручная команда restart создала событие нового рана и увеличила run ID.

### Ограничения

- полный 30-минутный soak-тест предусмотрен командой, но пока не зафиксирован в
  истории как выполненный;
- UDP не гарантирует доставку, поэтому протокол рассчитан на повторяемые actions
  и свежие observations.

## Этап 2 — навигация в комнате

### Цель

Перемещаться по комнате, обходить препятствия и проходить через выбранную дверь.

### Реализовано

- экспорт `GridCollisionClass` для всей комнаты;
- преобразование world position ↔ grid cell;
- блокировка стен, камней, объектов и ям;
- A* с Manhattan heuristic;
- поиск ближайшей проходимой клетки;
- steering по waypoint;
- детектор застревания;
- автоматическое перепланирование;
- движение к произвольной точке;
- выбор ближайшей открытой двери;
- подтверждение прохода по изменению room index;
- отключение `PauseOnFocusLost` для фоновой автономной работы.

### Проверка

- 100 из 100 синтетических маршрутов построены успешно;
- цель `(320, 280)` достигнута за 63 управляющих кадра;
- конечная позиция `(316.81, 280)`;
- живой проход через дверь: комната `84 → 58`;
- проход занял 89 управляющих кадров;
- перепланирований: 0;
- protocol probe после смены комнаты успешен.

### Возможности после этапа

Бот умеет ходить к заданной точке и проходить через открытую дверь. Он ещё не
принимает стратегические решения о маршруте этажа и не умеет вести бой.

## Дополнение — визуализация внутреннего представления

### Цель

Показывать в видео не изображение игры, а структурированное состояние, которое
получает алгоритм.

### Реализовано

- схематичная collision grid;
- игрок и вектор скорости;
- враги и их здоровье;
- вражеские снаряды и направления движения;
- pickups и двери;
- реальная текущая цель контроллера;
- путь A*;
- пассивный observer-протокол, не перехватывающий управление;
- полностью английский интерфейс;
- Studio с живым изображением игры и world model;
- режим `side`: игра слева, модель справа;
- режим `reels`: игра сверху, модель снизу;
- Isaac остаётся в оконном режиме.

### Ограничения

- при отсутствии активной цели контроллера показывается `NONE / IDLE`;
- прогноз вражеских снарядов и карта опасности относятся к этапу 4.

## Этап 3 — стрельба по одиночным врагам

### Цель

Самостоятельно выбирать противника, стрелять с упреждением и очищать простую
боевую комнату без сложного уклонения.

### Реализовано

- сохранение текущей цели между кадрами и переключение после её уничтожения;
- выбор ближайшего доступного врага;
- решение задачи перехвата для постоянной скорости цели;
- публикация прогнозируемой точки попадания как текущей цели визуализатора;
- одновременные движение и стрельба;
- приближение, отход и орбитальное позиционирование по дистанции;
- запрет движения в заблокированную клетку collision grid;
- экспорт слёз игрока с координатами, скоростью, уроном и физикой падения;
- счётчики убийств, смен целей, здоровья и уникальных слёз.

### Проверка

- живая комната с 2 врагами очищена автоматически;
- время: 3,578 секунды, 104 управляющих кадра;
- уничтожено врагов: 2, потеряно здоровья: 0;
- отдельный telemetry-тест: 38 наблюдений и 7 уникальных слёз за 2,5 секунды;
- обнаружена и исправлена несовместимость Repentance+: `TearFlags` является
  `BitSet128 userdata`, а не обычным числом.

### Возможности после этапа

Бот может войти в простую комнату, выбрать врага, вести его с упреждением,
поддерживать дистанцию, уничтожить несколько целей и остановиться после зачистки.
Визуализатор отображает и боевую цель, и летящие слёзы игрока.

### Ограничения

- нет прогноза траекторий вражеских снарядов и активного уклонения;
- выбор цели пока основан главным образом на расстоянии, без каталога опасности;
- критерий 90% требует отдельного набора воспроизводимых боевых сценариев.

## Этап 4 — уклонение от снарядов

### Реализовано

- прогноз ближайшего сближения со снарядом на горизонте 24 кадров;
- оценка предпочтительного движения, остановки, четырёх осей и диагоналей;
- проверка нескольких точек траектории по collision grid;
- штраф за дистанцию столкновения и оставшееся до него время;
- независимые векторы движения и стрельбы;
- краткосрочный прогноз контакта с врагами в плотной комнате;
- метрики кадров со снарядами, опасности, уклонения и минимального clearance.

### Проверка

- unit-тест встречного снаряда выбирает перпендикулярное уклонение;
- удаляющийся снаряд не изменяет предпочтительное движение;
- во время уклонения стрельба по цели продолжается;
- второй враг учитывается как контактная угроза;
- первый live stress-тест: 283 кадра со снарядами, 152 опасных кадра и 152
  выполненных уклонения в комнате с 14 врагами;
- после добавления контактного риска бот очистил комнату с 4 врагами, пережил
  полный 45-секундный бой с 10 врагами и остановился по тайм-ауту, а не смерти;
- суммарный урон в двух этих комнатах составил 2 полусердца;
- проходят 18 автоматических тестов.

### Ограничения

- первый stress-тест закончился смертью из-за плотного контакта с врагами; этот
  случай привёл к добавлению контактного риска и regression-теста;
- лазеры, взрывы и эффекты площади пока не прогнозируются;
- количественное снижение урона требует benchmark на одинаковых seed.

Следующая крупная задача — полноценная зачистка комнаты и исследование этажа с
глобальной памятью, волнами врагов, подбором ресурсов и переходами этажей.

## Этапы 5–6 — зачистка и исследование этажа

### Реализовано

- постоянный граф комнат в пределах этажа;
- тип и посещённость целевой комнаты для каждой двери;
- выбор доступного frontier с приоритетом сокровищницы;
- BFS-маршрут через посещённые комнаты к удалённому frontier;
- фильтрация закрытых и уже посещённых ложных frontier;
- открытие запертой двери при наличии ключа;
- сбор достижимых бесплатных ресурсов и предметов;
- безопасный пропуск pickups, к которым A* не может построить путь;
- экспорт grid-люков и лестниц и контроллер перехода этажа;
- смена боевой цели после 120 кадров без нанесённого урона;
- расширенный допуск подхода к двери против колебаний steering.

### Проверка

- 26 автоматических тестов;
- застрявшая комната после переключения целей очищена: 3 врага за 18,172
  секунды, 0 урона;
- чистый исследовательский прогон: 6 уникальных комнат, 9 переходов, 4
  осмысленных возврата, посещена сокровищница, собраны trinket и бомба;
- циклы между комнатами устранены regression-тестом закрытого remote frontier.

### Ограничения

- критерий перехода Basement I → Basement II ещё не подтверждён;
- проверенный ран завершился `floor_explored_no_exit` до обнаружения босса;
- нет политики бомб для секретных дверей и полной экономики ключей/магазина;
- граф пока не сохраняется между перезапусками Python посреди этажа.

## Дополнение — автономный цикл комнат

Добавлена команда `python run_bot.py rooms --count 0`, которая непрерывно:

1. анализирует текущую комнату;
2. уничтожает доступных врагов;
3. выбирает открытый выход, по возможности не ведущий в предыдущую комнату;
4. проходит дверь и повторяет цикл;
5. записывает результат каждой комнаты в `runs/room_traversal.jsonl`.

Первая живая проверка прошла несколько переходов без ручного вмешательства,
включая зачистку комнаты 85 с двумя врагами. Это ранняя интеграция готовых
контроллеров, а не полноценное исследование этажа: глобальной карты комнат и
выбора стратегического маршрута пока нет.

### Интерактивное завершение рана

Добавлен режим `python run_bot.py runs`. Автоматический рестарт в нём отключён.
После смерти или остановки контроллера консоль показывает длительность, число
комнат, достигнутый этаж, убийства, полученный урон, количество наблюдавшихся
слёз и время боя. Затем контроллер ждёт `R` для нового рана либо `Q` для выхода.
Визуализатор и Studio этим режимом не запускаются.

Исправлено зависание после повторного рана: контроллер теперь немедленно
обрабатывает `game_end`, считает отсутствие телеметрии более двух секунд
завершением управления и показывает меню `R/Q` даже после внутренней ошибки.

Исправлен перезапуск с экрана смерти: Lua продолжает принимать команды через
`MC_POST_RENDER`, когда `MC_POST_UPDATE` уже остановлен. Python дополнительно
использует штатное удержание клавиши `R`, если Lua не подтвердил рестарт, и при
ошибке оставляет пользователя в меню `R/Q`, а не закрывает контроллер.
